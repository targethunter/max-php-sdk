# v2.0.0 Strict MAX Docs Sync Design

## Goal

Release `v2.0.0` as a strict synchronization with the current official MAX API documentation. Public SDK methods should represent documented MAX API methods only. Methods that are no longer supported or absent from the current method list are removed in this major release.

Official reference: https://dev.max.ru/docs-api

## Release Positioning

`v2.0.0` is a breaking release. It follows `v1.3.0`, which changes the default base URL to `https://platform-api2.max.ru/`.

This release does not attempt a full SDK rewrite. It removes unsupported public API surface and adds the documented pieces missing from the SDK.

## Breaking Changes

Remove `Chats::getAll()` because `GET /chats` is explicitly marked by MAX documentation as no longer supported since June 2026.

Remove `Chats::delete()` because `DELETE /chats/{chatId}` is not present in the current official method list.

Remove `Bots::update()` because `PATCH /me` is not present in the current official method list. `Bots::getMe()` remains as the documented `GET /me` operation.

## Supported Existing Methods

Keep these modules and methods because they map to documented MAX API methods:

- `Bots::getMe()`
- chat lookup, update, actions, pin, membership, admins, members methods that exist under documented `chats`
- `Subscriptions::getAll()`
- `Subscriptions::subscribe()`
- `Subscriptions::unsubscribe()`
- `Subscriptions::getUpdates()`
- `Upload::getUrl()`
- message list, send, update, delete, get by ID, video info, and answer callback methods

Long Polling remains available through `Subscriptions::getUpdates()` because `GET /updates` is documented, but README must state that MAX recommends Webhook for production and Long Polling only for development and testing.

## New SDK Surface

Add upload type constants for documented upload types:

- `image`
- `video`
- `audio`
- `file`

The SDK must not add or document `photo` as an upload type for `v2.0.0`.

Add `ClipboardButton` DTO for inline keyboard buttons with:

- `type = "clipboard"`
- `text`
- `payload`

Add a webhook secret helper that validates the incoming `X-Max-Bot-Api-Secret` header against the configured subscription secret using timing-safe comparison.

## Documentation Updates

README must include a `v1.x -> v2.0.0` migration section:

- `Chats::getAll()` removed; use Webhook or Long Polling updates to obtain `chat_id`.
- `Chats::delete()` removed because it is not documented.
- `Bots::update()` removed because it is not documented.
- `UploadType` constants should be used for upload type values.
- `ClipboardButton` is available for inline keyboards.

README must also document production guidance from MAX:

- use Webhook for production;
- Long Polling is for development and testing;
- webhook URLs must use HTTPS;
- webhook endpoint should listen on port 443;
- use trusted certificates;
- verify `X-Max-Bot-Api-Secret`;
- keep requests to `platform-api2.max.ru` within the documented 30 rps limit.

## Tests

Add or update PHPUnit tests for:

- removed methods are absent from `Chats` and `Bots`;
- `UploadType` exposes only `image`, `video`, `audio`, and `file`;
- `ClipboardButton` serializes to the documented payload shape;
- webhook secret helper accepts matching secret and rejects mismatched secret;
- existing `answerCallback` behavior remains intact with `callback_id` in query;
- full existing request tests continue to pass.

## Non-Goals

Do not rewrite the transport layer.

Do not migrate to PSR-18 or a new HTTP abstraction.

Do not rewrite all DTOs as immutable objects.

Do not include broad DTO nullability fixes in this scope unless a selected task directly requires one of them.

Do not change the `MAXClient` module access pattern.

Do not add a runtime rate limiter for the 30 rps limit; document the limit only.

## Open Compatibility Notes

This release intentionally removes public methods that are not present in the current official MAX documentation. If MAX later restores or documents those methods, they can be reintroduced in a later minor release with tests and README examples.
